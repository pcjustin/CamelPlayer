# Changelog

## 0.4.1

Upgrading from 0.4.0 changes nothing in the library or the settings.

Changed since 0.4.0:

- **A double-click on a folder no longer closes CamelPlayer:** on the Folders page, a double-click on a folder further down a scrolled list opened the folder with its first click, and the second click, landing as the list was replaced, named no row; CamelPlayer read it anyway and closed, in every version since 0.1.0. A click that names no row is now ignored, in the folder, album, artist, track and playlist lists alike.

## 0.4.0

Upgrading from 0.3.0: the library gains a table for waveforms (library schema 21), and a copy of the library as it was is kept beside it as `library.db.v20.bak`. 0.3.0 refuses the newer library, so to go back to it, close CamelPlayer and, in `%LOCALAPPDATA%\CamelPlayer`, replace `library.db` with that copy. The settings keep their schema.

Background library work now goes at the Low scan speed, for libraries that were scanned before too: set Settings › Library › Scan speed to High for the speed of 0.3.0. Waveforms for the tracks you have are made in the background between 01:00 and 05:00, or at once when a track plays; ReplayGain analysis's own speed setting is gone.

As with every new version, the first complete library scan reads every MP3, and every file an earlier version could not read, once more.

Changed since 0.3.0:

- **A file read slower than it plays waits instead of breaking up:** a file on a network share that plays at 1 MB/s or more, such as DSD256 at 2.8 MB/s over Wi-Fi, is read for a moment before it plays. If it reads slower than it plays, playback waits, with a yellow "Buffering, about N s" bar above the player bar, until the rest will arrive in time, then plays without a break, buffering up to 1 GB in memory; should reading fall behind later, it pauses to buffer again rather than play in pieces. A network player or AirPlay receiver takes the audio over the same network, so for one of those the file is read at less than its full speed while it plays, the wait is longer, and the next track is read when the current one ends. Pause stops the wait.
- **Waveform:** the playback bar's position slider shows the playing track's waveform, as in Roon: the played part in the accent colour, each track scaled to its loudest, a click or drag seeking and the pointer showing the time there. An audio analysis makes it: at once for the playing track and the next; for the rest of the library in the background after the scan, in a window set in Settings › Library (01:00 to 05:00 by default, or any time), at the scan speed; and with ReplayGain on, in the loudness analysis's own pass, so no track is decoded twice. DSD goes through playback's DSD-to-PCM converter. Waveforms are kept in the library and made again when a file changes; Settings turns them off.
- **Scanning by hand:** **Scan now** in Settings › Library scans every library folder, and **Scan this folder** in a folder's right-click menu on the Folders page and in the folder tree scans that folder and everything below it, for a change the library missed, such as a tag edited on a NAS. Both look only for what changed, by size and modification time, run at High, are unavailable while a scan runs, and say so when the folder is offline.
- **Scan speed:** Settings › Library sets how much the library's background work takes (scanning, covers, fingerprints and ReplayGain analysis): Low, the default for everyone, uses one worker of each kind, Medium half of High, High as many as each can use. Adding a folder or rebuilding the library runs at High with the work following it; playback still comes first at every speed, and a change reaches running work at once. ReplayGain analysis's own Throttled and Fast setting is gone, folded into the scan speed.
- **File details:** "File details" in every track's right-click menu, and Alt+Enter on a selected row, opens a window beside the main one: a section for each tag format the file carries (ID3v2 with its version, ID3v1, APEv2, Vorbis comment, MP4, RIFF INFO, DIIN), every text tag by name and key with all its values, a mark with the library's value where the library shows a field otherwise, and the technical data with the ReplayGain tags and the library's analysis; pictures, lyrics and binary tags are left out and nothing is written. Every name and value is selectable and copies, and Open folder shows the file in File Explorer. A file that cannot be read shows why and what the library keeps.
- **Lyrics:** the player bar's cover opens the lyrics over the window, on the cover blurred: embedded (Vorbis, ID3 USLT and SYLT, MP4) or from a `.lrc` beside the file, synced over unsynced; synced lines follow what is heard, a translation under the same stamp lit with its line, a click seeks there, and scrolling by hand pauses the following for 3 seconds. The album name, no longer the cover, opens the playing album.
- **Start with Windows:** Settings › Interface can have Windows start CamelPlayer at sign-in, in the notification area and paused; the entry follows a moved folder, and one turned off in Windows' startup settings is shown as off and left so.
- **AirPlay to several receivers at once:** while a receiver plays, the output menu checks others into the group, in step and while it plays; the volume panel moves the group in proportion with a slider for each receiver; a receiver taken by another source or gone leaves with a notice while the others play on; the group comes back with any of its receivers and after a restart. A single receiver can play Stereo, Left or Right from its gear in Settings › Audio outputs, so two single HomePods make a stereo pair.
- **The output menu takes a mouse click every time:** a click on an output could leave it drawn pressed without choosing it, for the rest of the session, while the keyboard still chose; the menu is now built anew each time it opens and a click chooses on the press.
- **Go to playing in a folder tree with many folders open:** the button and Ctrl+L read every open folder again and showed the track before the folders above it had opened, which then pushed it out of view; the tree now opens only the closed folders on the way and shows the track once they are open.

## 0.3.0

Upgrading from 0.2.3: the first start gives each backend's settings to the device it had selected and enables the device in use (settings schema 4). 0.2.3 refuses the newer settings file, so to go back to it, close CamelPlayer, delete `settings.json` in `%LOCALAPPDATA%\CamelPlayer`, and choose your output again.

As with every new version, the first complete library scan reads every MP3, and every file an earlier version could not read, once more; on an 86,000-file library on a NAS that took about 7 minutes.

Changed since 0.2.3:

- **An output menu in the player bar:** it lists the outputs you enabled, marks those not connected and switches between them. A playing track goes on from the audible position with the queue unchanged, and a paused track stays paused. This replaces the output backend and device lists in Settings.
- **Settings › Audio outputs** lists every device found by backend, each with a switch for the menu and a name of your choice, and "Windows default device (WASAPI)" as an entry of its own. A new installation selects that entry; an upgrade keeps the device in use.
- **Network players are found:** UPnP AV and OpenHome players on your network are listed in Settings › Audio outputs, each kept by its identity, so one with several addresses appears once and one that gets a new address is still the same player. Turning the first one on explains the firewall rule network players need, for this program on private networks only, and Settings says so if the rule is missing.
- **Playing to network players:** choose one in the output menu and CamelPlayer streams to it, one URL per track, as WAV, L16 or L24 at the source's format unless DSP or a permitted conversion changes it, and raw DSD as DSF to a player that declares it. Tracks of the same format follow each other without a gap through the player's next-track function or its OpenHome playlist. The player shows the title, artists, album, length and cover. A seek, a DSP change or another track is heard about a second later, and the position shown is what the player has played. The player's own pause, play, seek, next and previous are followed; another source taking it over stops CamelPlayer with that reason, and a player that disappears pauses as not connected. The signal path says bit-perfect to the renderer.
- **A network player another source takes over is left alone:** CamelPlayer stops and sends the player nothing more, no stop, pause, volume or track, until you play to it again, so the other source keeps playing. A player that takes the stream but does not play, as a speaker in standby, is reported within about 5 seconds. These notices name the reason in the interface's language: in use by another source, not connected, or did not start playing, with a reminder to check that the player is on and not in standby.
- **Settings for each network player:** the highest PCM and DSD sample rates and bit depth to send, DSF or PCM for DSD, gapless playback on or off, silence after a format change, and a device release 60 seconds into a pause. A change reopens the stream only when the path differs.
- **A network player's own volume:** read when the player is chosen, followed from its remote and app, and written only when you move the 0–100 slider or mute. Only the choice between it and Fixed is kept, never a level, and software volume is no longer offered for these players.
- **AirPlay receivers are found:** Apple's own receivers on your network, HomePods, Apple TVs and Macs, are listed with the network players in Settings › Audio outputs, kept by their device ID, so one with a new address or name stays the same receiver, and a stereo pair appears once. A receiver CamelPlayer cannot use says why: it takes only encrypted audio, asks for a password, takes another format or refuses the connection, as a Mac does.
- **Playing to AirPlay receivers:** choose one in the output menu and CamelPlayer sends 44.1 kHz/16-bit stereo, to both speakers of a HomePod pair, unchanged for a CD-format source, with other formats going through the conversion rule. Tracks follow without a gap and crossfades work; a seek or a pause flushes the receiver and what follows is heard about 2 seconds later, which the position shown allows for. Its volume is set from the slider, and the last level is kept for each receiver, starting at about -20 dB. If another source takes the receiver, or it stops answering, playback pauses and says so.
- **A settings window for each output:** the gear on a row in Settings › Audio outputs opens that output's own settings, whether it is in use or not, without leaving the output playing.
- **The language changes at once:** choosing another language in Settings › Interface applies it straight away, without a restart, and playback goes on.
- **Clearer settings and status:** the settings links show the section you are in, the output menu names how each output is reached, the status badges are easier to hit and their text is centred, and the search box fits a small window.
- **DTS-CD is decoded by a Rust core, and FFmpeg is gone from the program:** the WAV decoders hand DTS-CD files to CamelPlayer's own decoder, which plays the 5.1 core; a DTS-ES file plays as 5.1 rather than 6.1, its rear center kept in the surrounds. FLAC, WAV and AIFF keep their other decoders, ALAC plays with Symphonia alone, and a saved FFmpeg choice falls back to the format's default.
- **Starts sooner, with a small library log:** the log SQLite keeps beside `library.db` grew at every start and stayed after a clean exit, past a gigabyte on a large library, and reading it held up the start. It now stays small and goes when CamelPlayer closes; the first start of this version folds in what is there. On a library of 86,000 files the window appears in about 0.6 s and the library is usable in about 2 s.
- **Scanning an unchanged library writes nothing:** every scan rewrote each file's and folder's row.
- **Closing on a busy machine:** with every core busy a scan could hold the program open for minutes after its window closed, and starting it again seemed to do nothing. It now saves the queue first and leaves within seconds.
- **A long queue stays quiet while playing:** with more than 2,000 entries in the queue, saving the queue every 5 seconds made CamelPlayer read through the library to check the queue's files, about 26 MB each time for a queue of 55,000. It now checks only when files or library folders change, and once a minute.
- **The first scan of a new version goes on where it stopped:** that scan reads every MP3 and every file an earlier version could not read again, and if CamelPlayer closed before it ended, the next start began it all over. It now reads only the files it had not reached.
- **The highest PCM and DSD rates for each output:** every output but WASAPI shared mode and AirPlay can be given a highest PCM sample rate and a highest DSD sample rate, for a DAC or digital converter that carries less than the device announces, such as one that plays DSD128 and up as silence. PCM above the highest rate is resampled to the top rate of its own family: under 192 kHz, 352.8 kHz becomes 176.4 kHz and 384 kHz becomes 192 kHz. DSD above the highest DSD rate is modulated again at that rate by CamelPlayer's own modulator, DSD256 to DSD64 for one, and stays DSD with DSP bypassed; the signal path shows the step as processed. DoP follows the highest PCM rate, so under 192 kHz DSD128 plays by DoP as DSD64. Choosing a limit is the permission to convert above it. Converting DSD to PCM is also about twice as fast.
- **What is playing is marked everywhere:** the album wall, the album lists of search and artist pages, the Folders page and the folder tree mark the playing album or folder with the playing or paused icon and the accent colour, every folder on the way down to the track included, and follow a change of track, a pause and a stop at once. **Go to playing** at the top of the library, or Ctrl+L, scrolls to it on the page you are on, opening the folders on the way, and selects the track; elsewhere it opens the track's album.
- **Playing a folder plays on:** with Settings › Playback › When playing from a folder set to go on to the end of its library folder, playing a whole folder, by a double click or Enter in the tree, the folder's Play button or Play now in its menu, also goes on to the folders after it, as a track chosen in it already did. Play next and Add to queue still add that folder only.
- **Each output keeps its own settings:** every WASAPI endpoint, ASIO driver and Kernel Streaming pin has its own parameters and fixed or software volume, and a device chosen for the first time starts from the defaults. Following the Windows default uses the settings of whichever device is the default. Deleting a saved device clears its settings, name and place in the menu; found again, it starts from the defaults.

Fixed since 0.2.3:

- **A HomePod pair paired again lost its settings:** the Home app gives a stereo pair a new identity each time it pairs it, so the pair came back as a new receiver, turned off, beside the old one shown as not connected. It is now known by its two speakers and keeps its name, settings, volume and place in the output menu, and the old entry goes.
- **A FLAC with a large cover started slowly from a NAS:** the Symphonia decoder read the whole embedded picture, often 3 to 4.5 MB, before the first sound, which held a start back by up to 1.5 seconds over Wi-Fi and the preparation of the next track as long. It now leaves the pictures out, as the libsndfile decoder already did.
- **Exiting could crash CamelPlayer:** a timer of the Home page could tick after the window closed and end the program before it closed its library, which the next start then treated as an unclean exit. Exit now stops every timer of the window first.

## 0.2.3

Upgrading from 0.2.0, 0.2.1 or 0.2.2: the first start records when each file the library could no longer find went missing (schema 20), and deletes the folders removed from the library under an earlier version with everything of theirs, then compacts the library, which takes a few seconds once. The old library is kept as `library.db.v19.bak` in `%LOCALAPPDATA%\CamelPlayer`. Those versions refuse the newer library, so to go back to one of them, close CamelPlayer, delete `library.db`, `library.db-wal` and `library.db-shm`, and rename `library.db.v19.bak` to `library.db`; what changed since the upgrade, such as plays and favorites, is lost that way.

Changed since 0.2.2:

- **Playback takes far less CPU:** the window followed the position 20 times a second and still did while minimized; it now shows it four times a second and stops while minimized, current again at once when restored. The ReplayGain analysis no longer reads the whole library every 10 seconds to count its progress, only while Settings shows it. Playing FLAC took 15–20 % of one core on a 2015 laptop and now takes 2–3 %.
- **An MP3 from a NAS is read once:** where the library knows its exact length (from a Xing or Info header, or from playing the file before), mpg123 no longer reads the whole file a second time while it plays, nor the next track ahead of time. The first seek starts that reading, as the seek index needs it.
- **A folder removed from the library leaves it:** its tracks went out of sight but stayed in the library file, with their tags, covers, plays and favorites, so the file only grew. Removing a folder now asks first, naming how many tracks, plays, favorites and playlist entries go, then deletes them with the folder's queue and playlist entries and the thumbnails of its covers, and shrinks the file. Favorite artists and composers and artist pictures stay, as they belong to the names. Adding the folder again scans it as new.
- **Building the library gives way to playback:** while a track plays, reading the library from the same disk or NAS goes on with one worker only while the player holds its full 10 seconds of audio ahead, and waits otherwise, so a start or a seek never waits for it; other storage is read with one worker, and full speed returns when playback pauses or stops. ReplayGain analysis at full speed now gives way too. During Settings › Rebuild library of an 86,000-file NAS, starts, seeks, track changes and the window's answers took as long as when idle, with no dropout. While nothing plays, CamelPlayer no longer reads its whole library file every second to look for files to fingerprint.
- **Files gone for 30 days leave the library:** a file missing from a folder still in the library keeps its plays and favorites for 30 days, so a moved or renamed file found in that time keeps them; after that it is deleted like a removed folder's files. Only a complete scan of a reachable folder counts a file as missing, never one of a NAS that is off. Files already missing start their 30 days at the upgrade.
- **Track list columns can be sized:** drag the dividers between the title, artist and album headers to make those columns wider or narrower, down to 80 pixels each. This works on the Tracks page, in search results, on an artist's page, on an album with several artists and in playlists. All lists share the same widths, which scale with the window and are kept across restarts. Double-click a divider, or reset the interface in Settings › Reset and data, to return to the default. Search results and an artist's tracks now have column headers, and the headers of a playlist line up with its columns.
- **A track played from a folder can play on to the end of its library folder:** Settings › Playback › When a track plays from a folder, off by default. When it is on, a track clicked on the Folders page, or double-clicked in the folder tree, plays its folder from that track on and then every folder after it in the Folders page's order, up through the folders above, until the library folder ends. For example, an album's DISC 01 goes on to DISC 02. The track starts as quickly as before, and the rest joins the queue a few seconds later; for a 55,000-track library folder, the queue is complete about 4 seconds after the click.
- **Large folders play and queue sooner:** listing a folder's tracks read each of its subfolders separately, which took about a minute for a 55,000-track library folder. Queueing them then looked up every track separately, which took 15 seconds more. Now each takes about a second.

Fixed since 0.2.2:

- **Long titles were cut off mid-character** in album track lists, search results and the Artists, Composers and Genres lists, with room left in the row: a title too long for its room now ends in "…" and shows its whole text when the pointer rests on it, as other long texts in the lists, cards, queue and player bar now do. On an album whose tracks share one artist, the titles take the room the empty artist column leaves, and the album's track list follows the window's width instead of stopping at 820 pixels. A long artist credit ends in "…" too instead of being cut off mid-name, and on an artist's page it no longer runs over the album beside it.

## 0.2.2

Upgrading from 0.2.0 or 0.2.1: the first start adds an index of the artists to the library (schema 19), which takes a second or two, and keeps the old library as `library.db.v18.bak` in `%LOCALAPPDATA%\CamelPlayer`. 0.2.x refuses the newer library, so to go back to it, close CamelPlayer, delete `library.db`, `library.db-wal` and `library.db-shm`, and rename `library.db.v18.bak` to `library.db`; what changed since the upgrade, such as plays and favorites, is lost that way.

Changed since 0.2.1:

- **MP3 plays with mpg123 alone:** Settings › Decoders no longer offers FFmpeg, Symphonia or dr_mp3 for MP3. Measured from a NAS against them, mpg123 starts and seeks as quickly as the quickest, and it alone measures an MP3's exact length while it plays and then seeks exactly.
- **An MP4 whose sound is MP3 is no longer listed:** mpg123 reads MP3 streams only, so the scan passes such a file over and playing one reports it as unsupported.
- **AAC plays with Symphonia alone and ADPCM with libsndfile alone,** so Settings › Decoders lists only FLAC, ALAC, WAV and AIFF. A setting that named another decoder for MP3, AAC or ADPCM now plays with the one left.
- **AAC and MP3 always decode to 24-bit PCM:** the 16-bit option is gone. A device that takes only 16-bit gets them reduced with dither when conversion is allowed, shown as processed.
- **Suggestions for a word in many titles come at once:** the artists among them are looked up in an index of artists alone. With 100,000 tracks that all hold the word, the suggestions took 77–120 ms and now take about 7 ms.
- **MP3s from a NAS start and seek at once:** mpg123 read the whole file before the first sound to learn its exact length, which took 5–9 s over Wi-Fi. Playback now starts after the first frames, in under a second from the same NAS; the length the library knows shows at once and becomes exact while the file plays. A seek before the whole file has been read goes at once to where the target is estimated to be, by the Xing table or the length, and seeks land exactly once the file has been read: from the NAS a seek to 90 % right after the start plays within about half a second.
- **Another track starts at once while one plays:** a change by hand to a file in the format the device already plays keeps the device running instead of closing and reopening it, which cost the Chord DAVE's ASIO driver about half a second each time. Choosing a track from a NAS no longer asks the NAS about every track queued with it, nor how the chosen file is spelled, which the scan already stored: while the playing MP3 was read from the NAS, each question waited behind it, and a change took 1.4–6.7 s. On the same NAS a change now takes well under a second.
- **Symphonia 0.6.1,** the decoder for AAC and the default for ALAC, replaces 0.5.5.
- **dr_flac 0.13.4 and dr_wav 0.14.6** replace 0.13.3 and 0.14.5, with fixes for malformed FLAC metadata and block sizes, 32-bit FLAC, and AIFF sample rates.

Fixed since 0.2.1 (files an earlier version refused are read again once by the first scan after the update, so those below appear by themselves):

- **MP3 files whose audio does not follow the tag at once** were refused: a second ID3 tag, padding or other bytes between the tags and the first frame. The first frame is now found past them.
- **M4A files with a one-byte genre** were refused by Symphonia, the AAC decoder and the default for ALAC, because it reads the file's tags itself and gave up on that one. Symphonia now skips the tags, which CamelPlayer reads with TagLib anyway.
- **MP4 videos:** Symphonia took the picture track for the sound and refused the file. The first track it can decode now plays, so the sound of a music video or concert video plays like a track.
- **MP3s with a VBRI header** (written by Fraunhofer encoders) started with 26 ms of silence from mpg123, which decoded the VBRI frame as sound; they now start with their first audio frame.
- **An MP3 whose last frame is cut short,** such as by an ID3v1 tag written over the end of the file, ended in an error with mpg123 and skipped to the next track; it now ends normally.
- **MP3 lengths in the library could be wrong,** such as 1:29 for a 1:48 track with a VBRI header, which was estimated from the file's size, or seconds too long for a file without a Xing or Info header, whose estimate counted the cover art in its tags as sound. The first scan after the update estimates such lengths again, from the VBRI header or from the sound alone, and any MP3 length that differs from the decoded one is corrected once the track has played.
- **Symphonia refused a whole file** at an AAC frame it could not decode. Such a frame now plays as silence of its length.
- **macOS `._` files** (AppleDouble files with Finder data, left beside the music on a NAS) counted as audio files that could not be read; the scan now passes them over.

## 0.2.1

New since 0.2.0:

- **ADPCM WAV files:** IMA and Microsoft ADPCM, whose 4-bit codes were refused before, play as exact 16-bit PCM, marked as a lossy source. Settings › Decoders has an ADPCM decoder of its own, libsndfile by default. Audio files an earlier version could not read are read again once by the first scan after an update, so ADPCM files already in a library folder appear.

Changed since 0.2.0:

- **Conversion is on by default,** for earlier settings too: when a device does not take a file as it is, CamelPlayer resamples, downmixes, reduces the bit depth or decodes DTS, and the signal path shows it as processed. **Skip it and tell me** in Settings › Playback still plays bit-perfect only.

Fixed since 0.2.0:

- **DTS-CD files played as loud noise.** A WAV file that holds a DTS surround bitstream instead of PCM is now recognized by its content and never played as PCM. With conversion, the chosen WAV decoder reads it, FFmpeg's DTS decoder decodes it and it is downmixed to stereo; without, it is skipped as unsupported.
- **A rate the driver offers but cannot run,** such as 64 kHz on Chord's ASIO driver, ended in a driver error. It now counts as a rate the device does not take: with conversion it is resampled, otherwise skipped as unsupported.
- **WASAPI polling could stop with an error** right after the device changed format: the Chord DAVE then reported room it did not yet grant. The next polls ask again.
- **Online lookups named no version:** the update check, MusicBrainz and Wikimedia received "CamelPlayer/CAMEL_VERSION" as the User-Agent; they now receive CamelPlayer's version.

## 0.2.0

Upgrading from 0.1.0: the first start moves the library to a newer format (schema 18) and keeps the old one as `library.db.v17.bak` in `%LOCALAPPDATA%\CamelPlayer`. 0.1.0 refuses the newer library, so to go back to it, close CamelPlayer, delete `library.db`, `library.db-wal` and `library.db-shm`, and rename `library.db.v17.bak` to `library.db`; what changed since the upgrade, such as plays, favorites and ReplayGain analysis, is lost that way. 0.1.0 reads the settings too, but keeps only those it knows, so the DSP, volume and Discord settings go when it saves.

New features since 0.1.0:

- **Parametric EQ** in Settings › DSP. It starts with five bands and the editor adds up to ten, with peaking, shelf, low and high pass (6 to 48 dB per octave), band pass, notch and all-pass filters, each on both channels or one. Drag a point on the response curve to change frequency and gain, and the mouse wheel to change Q. Presets can be saved, Reset returns to the five flat bands, and Equalizer APO and AutoEq files can be imported and exported.
- **Headphone crossfeed** (bs2b) with the Default, Chu Moy and Jan Meier presets or a custom cut-off and feed.
- **Convolution** with an impulse response: a mono, stereo or true-stereo .wav, or a .zip with one per sample rate. A missing rate is converted and cached; responses up to 1,048,576 samples per channel run without latency, and after the last track their end plays out.
- **Software volume:** volume stays fixed by default, for a DAC or amplifier; software volume turns the player bar's volume button into a vertical slider (−80 to 0 dB) with mute, and at 0 dB playback stays bit-perfect.
- **ReplayGain:** Track, Album or Auto (album gain while the queue plays an album in order), with preamps for tracks with and without values and clipping prevention by peak. Values come from the files' tags; tracks without them are analyzed in the background (EBU R128 with libebur128) while ReplayGain is on, queued tracks first, throttled or fast, and the results stay in the library, never in the files.
- **Crossfade** of 1 to 10 seconds, off by default: natural changes, Previous/Next and playing another track or album overlap with an equal-power fade, while an album played in order stays gapless. Pause, stop, seeking and restarting a track act at once. A track in another format is converted to the open one, so nothing reopens mid-track; raw DSD never crossfades.
- **Signal path panel:** the bit-perfect lamp opens a panel above the player bar with the verdict and the route from the file's format to the device's, then one row per step in three stages, source, processing and output, each with the format after it and a colored dot for bit-perfect, lossless conversion, processed or lossy source. A processing stage with no steps says that nothing there changes the signal.
- **The DSP chain:** EQ, crossfeed and convolution work in an order you can change, after one automatic preamp that keeps the whole chain from clipping. The DSP button in the player bar turns each on or off and switches EQ presets. Changes are heard within about a quarter of a second without a gap; while nothing changes the signal, playback stays bit-perfect.
- **Discord:** Settings › Interface can show what's playing on Discord, off by default: the title, the artists, the album on the cover, the progress bar and the signal path's state as a small dot, with the title in your friends list. Pause and stop clear it, and only track changes, seeks and state changes reach Discord. **Also show the cover** sends the file's own cover through an anonymous Cloudflare quick tunnel that runs only while music plays; cloudflared, a pinned release checked against its SHA-256, is downloaded the first time.

Changed since 0.1.0:

- **Search ranks results:** names that match whole come first, then names that start with the search, then names with a word that starts with it, then the rest. Artists always rank; tracks and albums rank when a search matches up to 2,000 tracks, and a broader one lists them by title as before.
- **The Tracks list has column headers:** click Title, Artist, Album or Length to sort by it, and again to reverse it.
- **Play on an album or folder page plays it at once;** the arrow beside it offers playing it next and adding it to the queue.
- **The player bar is two rows high:** the timeline row holds only the timeline and the time, and the badges and the DSP button sit beside the volume, favorite and queue buttons, so nothing moves the timeline. The format line is gone; the signal path panel shows the route. Volume is one button: a lock on it marks fixed volume, and with software volume it opens a vertical slider above it.
- **Settings › DSP is three cards,** Volume and ReplayGain, Crossfade, and DSP processing, and each long note shows its first sentence with Learn more.
- Screen readers find the page titles and the settings cards as headings, and hear Play or Pause and the repeat mode as they are. Repeat is a toggle like Shuffle. Counts show digit grouping (70,715), album titles wrap to two lines, the player bar's cover has a tooltip, and the fields of crossfade and ReplayGain are disabled while those are off.

Fixed since 0.1.0:

- With a theme in Settings › Interface other than the Windows one, the colors the player sets itself (the playback state, the output lamp, the DSP button, the signal path dots, the EQ editor, Home's tiles and chart and an album's formats) followed Windows and could be unreadable. They now follow the app's theme and change with it.

## 0.1.0

New features since 0.0.1:

- **More formats:** ALAC, WAV, AIFF, AAC-LC and MP3 join FLAC, each with its own decoder choice. AAC and MP3 decode to 24-bit (or 16-bit) PCM with encoder delay and padding trimmed for exact length and seeking. Files are recognized by their content, not their extension.
- **DSD:** DSF and DSDIFF files play as native DSD on ASIO or as DoP on every backend, up to DSD512 where the device supports it. DSD can also be converted to PCM at 88.2, 176.4 or 352.8 kHz.
- **Gapless playback** between tracks of the same format.
- **Conversion only with permission:** when a device does not take a file as it is, CamelPlayer skips it by default. It can instead resample (libsoxr), downmix surround to stereo or reduce the bit depth with dither, and it then shows the path as processed.
- **WASAPI shared mode**, and WASAPI following the Windows default device. A device you selected yourself is never silently replaced by another one.
- **Output settings for every backend:** fixed sample rate, pre-decode amount, silence after a format change, device release after pausing, polling buffer, MMCSS task and priority, device period, sample format, ASIO buffer and channels, and Kernel Streaming mode and buffers. The ASIO driver's callback thread joins MMCSS Pro Audio when the driver leaves it at normal priority, and late callbacks are reported in the device details.
- **Signal path display:** badges show bit-perfect, processed, lossy source and raw DSD playback. The format line expands into every processing step. The Settings status area lists the output format, mode, device buffer, underruns, and any requested setting the device replaced.
- **Music library:** add folders on local drives or NAS shares, several at once. Scanning runs in the background and follows changes automatically. Offline folders keep their tracks, and moved files keep their play history, favorites and playlist entries.
- **Library browsing:** a Home page, an album wall sorted by title, artist, year or date added, and artist, composer, genre and year lists. There is also a sortable track list, album details by disc with each album's formats, and folder pages, all with cover art. A folder page plays the whole folder from its Play button and shows each track's number on its album and its file name. A jump bar beside the artist, composer, genre and album lists goes straight to #, A–Z, kana or Han, and album covers are sized so that every row fills the window.
- **Folder tree:** Settings › Interface can show the Folders page as one tree in foobar2000's style, with track counts, file names and the folders you left open.
- **Artist names:** a credit that names several artists, such as "Aimer with chelly" or "A feat. B", counts each of them among the artists and composers, and each name on an album page and in the player bar opens that artist. "&", "," and "/" divide names where at least one part also appears on its own, while bands such as "Bob Marley & The Wailers" keep their names.
- **Artist and composer pages:** the ten most played tracks, the artist's own albums and the albums they appear on, each with View all.
- **Artist pictures** on artist and composer pages and in the Artists and Composers lists: your own picture, a picture in the artist's folder or tracks, or, once you allow it, one from Wikimedia Commons with its author and license. Several artists of the same name can be told apart, and the online lookup can be turned off in Settings.
- **Search** from the title bar (Ctrl+F) with suggestions as you type, including Chinese and Japanese text.
- **Play queue:** play next, add to the end, reorder, remove and save as a playlist, with shuffle, repeat and track history. The queue and position are restored at the next start. Album, folder, track, artist, search, playlist and smart-list pages mark the track it is on, playing or paused.
- **Autoplay:** when the queue ends, random library tracks keep playing.
- **Playlists:** create them from any selection, then rename, reorder, remove entries, and import and export M3U8 files.
- **Favorites** for tracks, albums, artists and composers. The Artists and Composers lists can show only their favorites.
- **Smart lists:** recently added, most played, last played, favorite tracks, favorite albums, favorite artists and never played.
- **Listening page:** listening time and plays for today, this week, this month, this year and all time, with this month's time, plays and most played album on Home. The chosen period shows a listening-time chart, the most played albums, artists and tracks by plays or listening time, and the play history. The statistics of selected tracks can be reset from their right-click menu.
- **Windows integration:** media keys, the volume flyout and the lock screen show and control playback. System-wide hotkeys can be changed, and keyboard shortcuts work while the window is in front. CamelPlayer keeps running in the notification area after its window closes, and only one copy runs at a time.
- **First-run guide** for choosing the look, adding music folders and choosing the output.
- **Light and dark themes**, or the Windows setting, switched at once from Settings or the first-run guide.
- **Settings resets and data:** reset playback, the interface, the library, the cover cache, the listening statistics or everything, and see where data is stored.
- **Automatic updates:** CamelPlayer checks GitHub Releases at startup and daily, and after you confirm it downloads and verifies the new version, installs it and restarts. A failed update is undone.
- **Installation check:** the first start of each version compares the program files with the release's list, and Repair downloads the same version again to replace damaged or missing files.
- **Damaged data recovery:** a damaged settings file comes back from the copy saved at the previous start, and a damaged library from its daily backup; a banner says what was repaired. Data written by a newer version is left untouched, with a message instead of a silent exit.
- **Diagnostic bundle:** Settings › About saves logs, settings, the output devices with the formats they accept, the installation check and the newest crash report in one zip for problem reports. Paths are left out unless you include them.
- **Interface in English and Traditional Chinese.**
- **Portable release:** a zip file with no installer, with its user guide in English and Traditional Chinese, third-party notices, the corresponding third-party source and SHA-256 checksums.
